# PRD：AI 官方资讯结构化知识库（面向中文用户）

## 1. 背景与问题

当前 AI 领域最新、最权威的信息几乎都来自英文一手信源（官方博客、论文、发布会、监管文件）。对英文不擅长的用户存在三重障碍：

1. **语言门槛**：官方信息全英文首发，理解慢、门槛高。
2. **信息失真**：转而依赖中文自媒体的二次加工内容，转译/解读过程中容易丢失关键信息、断章取义，甚至传播错误结论。
3. **信息过载与重复**：大量自媒体对同一事件反复搬运、洗稿，用户花大量时间刷信息流，得到的却是碎片化、重复的内容，无法建立系统性认知。

## 2. 产品定位

**把 OpenAI / Anthropic / Google DeepMind / Meta 等官方一手信源，自动采集、去重、溯源、结构化中文呈现，让用户用官方级别的准确度、系统化的组织方式，替代刷自媒体的碎片阅读。**

产品形态：结构化知识库 / 仪表盘（Web 应用）。

### 差异化对比

| 对比对象 | 差异点 |
|---|---|
| 自媒体资讯 | 不失真、可溯源到原文、自动去重合并重复报道 |
| 纯翻译工具 | 不是逐篇翻译文章，而是提炼、分类、组织进知识体系 |
| 新闻聚合器（如 TechMeme） | 官方信源优先 + 中文本地化 + 结构化知识组织，而非单纯新闻流 |

## 3. 核心设计

### 3.1 信源采集层

- 固定信源白名单，而非通用爬虫：
  - 公司官方博客/新闻页（OpenAI、Anthropic、Google DeepMind、Meta AI 等）
  - arXiv 论文（按机构筛选）
  - 官方 X/Twitter 账号
  - 官方发布会/直播
  - 主要监管机构文件（如美国 AI 行政令、EU AI Act 更新）
- 优先级：公司一手发布 > 论文原文 > 监管/政策文件

### 3.2 溯源与可信度

- 每条知识条目必须挂载原始来源链接、发布时间、原文关键段落引用
- 用户可一键跳转原文，建立"可验证"的信任感 —— 这是相对自媒体的核心差异化

### 3.3 去重与合并

- 同一事件被信源多次提及（如模型发布 + 官方博客 + 论文 + 官方账号预热）自动识别合并为一个知识条目，避免用户重复阅读

### 3.4 结构化组织（区别于新闻流的关键）

- **多维分类**：主题（模型发布 / 研究论文 / 产品更新 / 政策监管 / 公司动态）、机构、时间线
- **关联展示**：标注事件间的依赖关系（例如"该发布基于 X 论文的技术"），帮助用户建立体系化认知而非孤立信息点

- **按产品/模型形态的演进脉络**：除了时间线和分类，额外提供「技术路线时间轴」视图，把碎片事件归位到某条技术演进主线上的关键节点，而不是平铺罗列。例如：
  - **模型能力路线**：快思考（直接生成）→ 慢思考/推理（reasoning/CoT、o1 类）→ 多模态（图文/音视频）→ 任务执行/自主行动（agentic）
  - **对话/助手产品路线**：单轮对话 → 检索增强（RAG）→ 推理-行动循环（ReAct）→ 标准化工具调用（MCP）→ 通用工具使用/多智能体协作
  - 每条主线标注关键转折节点（谁最早提出、哪篇论文/发布奠定范式、后续厂商如何跟进），让用户看到的不是"又发布了一个新模型"，而是"这个技术走到了发展脉络的哪一步、为什么重要"
  - 这类路线图是编辑/结构化的重活，MVP 阶段可先人工维护 1-2 条主线（如"推理模型路线"），验证用户是否认可这种呈现方式，再考虑半自动化归类

- **关键人物（KOL）维度**：在机构维度之外增加"人物"维度，记录 Sam Altman、Dario Amodei、Demis Hassabis、Ilya Sutskever 等核心决策者/首席科学家通过官方渠道（公司博客署名文章、官方采访、财报电话会、公开演讲）发表的关键判断和预测。仍遵循"仅官方一手"原则 —— 只采集可溯源到本人原话的内容，不采集自媒体转述的"某某说过"
  - 与技术演进时间线互为印证：把人物的关键判断/预测作为标记点，叠加在同一条技术演进时间轴上，用户可以看到"谁在什么时间点说了什么，后续技术发展是验证了还是打脸了这个判断"，用于评估人物/机构的行业判断力和影响力
  - 展示形式：同一时间轴上，技术里程碑（发布/论文）与人物发言用不同样式的节点区分，但共享坐标便于交叉对照；一个模型发布事件的详情页可关联展示"此前谁曾对此有过预测或表态"

### 3.5 翻译与摘要原则

- 中文结构化摘要为主，专有名词/术语保留英文原文（避免翻译失真、方便用户对照检索原文关键词）
- 摘要提炼关键事实（做了什么、影响是什么、和之前的关联），而不是机器直译全文

### 3.6 订阅与追踪

- 用户可关注特定主题/机构/技术方向，只接收结构化更新，而不是被全量信息轰炸

## 4. MVP 范围

先收窄到「模型与研究发布」这一类目，跑通闭环，验证准确度与翻译质量后再扩展：

- **信源**：OpenAI / Anthropic / Google DeepMind / Meta AI 官方博客 + 对应 arXiv 论文
- **闭环**：抓取 → 去重（内容相似度匹配）→ 结构化摘要提取（含溯源）→ 分类打标 → 时间线/分类展示
- **暂不做**（留作二期）：关联知识图谱、政策监管类目、个性化订阅、问答交互、完整的技术路线时间轴（先人工维护 1-2 条主线验证）

## 5. 商业模式（待讨论）

- 早期：免费开放，用内容准确度和信息颗粒度建立用户信任和口碑
- 后期：订阅制（深度关联分析、个性化追踪、API/数据访问）

## 6. 开放问题 / 待细化

- 技术路线主线（如"推理模型路线"）的判断标准与编辑流程如何定义？谁来维护？
- KOL 名单范围如何界定与更新（仅限公司高层/首席科学家，还是扩展到核心研究员）？
- 去重算法的相似度阈值、多语言/多信源匹配的具体技术方案
- 后续技术栈选型（采集 pipeline、存储、前端框架）
